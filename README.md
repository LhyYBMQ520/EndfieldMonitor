# EndfieldMonitor

EndfieldMonitor 是一款 **Windows 透明桌面硬件监控挂件**。中央圆环显示系统电池电量，上下两个监控位可以分别显示 CPU 温度、GPU 负载、内存占用等数据。适合放在桌面一角，随时查看电脑状态。（谁不想桌面上有一个协议核心呢嘻嘻~）

这是一个**免费、非官方的《明日方舟：终末地》同人项目**。仪表外观参考了游戏界面，由项目作者使用 AI 工具（×）许愿（√）复刻，与游戏官方无隶属关系，也未获官方背书。

仪表使用 C# 和 WPF 原生绘制，日常使用不需要联网，也不依赖浏览器或 WebView。

## 快速开始

**系统要求：** Windows x64，推荐使用仍受支持的 Windows 11 版本。Windows 10 用户请先核对微软的 [.NET 10 系统支持列表](https://learn.microsoft.com/dotnet/core/install/windows#supported-versions)。本项目目前只构建 `win-x64`，不提供原生 ARM64 或 32 位版本。

1. 如果你已有 `win-x64` 发布包，将它**完整解压**到一个文件夹即可使用。如果没有发布包，可 VS2026 打开解决方案文件从源码构建。
2. 双击 `EndfieldMonitor.exe`，先用普通权限运行。
3. 点击挂件中央的 **「电能报告 ···」**，打开监控设置。分别进入「上方监控」和「下方监控」，按设备名或传感器类型搜索并选择读数。
4. 要更改窗口状态，在任务栏通知区域右键点击挂件图标。如果找不到图标，先展开系统托盘的隐藏图标列表。

## 使用说明

### 移动、缩放和窗口状态

| 操作 | 使用方法 |
| --- | --- |
| 移动挂件 | 未锁定时，拖动仪表上不是按钮的区域。 |
| 调整缩放 | 从托盘菜单或设置面板的「显示」页选择缩放比例（60%–160%）。 |
| 保持置顶 | 在托盘菜单中开启「窗口置顶」。置顶与锁定相互独立，不保证覆盖独占全屏应用。 |
| 让鼠标穿透 | 在托盘菜单中开启「锁定挂件」。挂件仍然可见，但鼠标点击和滚轮会交给它下方的窗口。 |
| 解锁或找回挂件 | 取消托盘菜单里的「锁定挂件」，或选择「打开监控设置」，后者会同时显示并解锁挂件。窗口位置不便操作时，选择「恢复默认位置」。 |
| 找回窗口 | 点击「显示桌面」、通过托盘隐藏挂件，或挂件被其他窗口挡住后，左键双击托盘图标即可恢复挂件并将它带到前面。挂件已显示时也可以双击；双击不会把它隐藏。 |
| 隐藏或退出 | 托盘菜单的「隐藏挂件」只隐藏窗口，托盘和后台采集仍继续运行，窗口动画暂停。点击挂件右上角的「×」或托盘菜单的「退出」会结束程序。 |

左键双击托盘图标时，挂件会在当前层级前移一次；未锁定时还会尝试成为 Windows 的当前活动窗口，锁定时则保持鼠标穿透，不接管键盘焦点。首次启动或再次运行 EXE 也会显示并前移挂件，但不会主动激活。双击不改变「窗口置顶」设置；如需持续显示在普通窗口上方，请手动开启该设置。

如果托盘图标不可用，可在 EXE 所在目录执行这些命令，控制正在运行的实例：

```powershell
.\EndfieldMonitor.exe --unlock        # 解锁并显示
.\EndfieldMonitor.exe --reset-window  # 恢复默认位置并显示
.\EndfieldMonitor.exe --settings      # 打开监控设置
.\EndfieldMonitor.exe --hide          # 隐藏挂件
.\EndfieldMonitor.exe --exit          # 退出程序
```

### 选择监控数据

- 上下两个监控位可以单独配置传感器、显示名称和小数位数。单位由程序根据读数自动换算；名称留空时使用默认名称。
- 首次运行时，上方优先选择 CPU 封装温度或对应的 CPU 温度传感器，下方优先选择独立显卡的核心负载。已选传感器暂时不可用时，程序不会悄悄换成别的读数。
- 「显示」页可以调整挂件缩放或关闭粒子动画；「状态」页可以查看采集状态、运行权限、渲染帧率和配置路径。

### 普通权限、管理员权限与电池状态

GPU、CPU 负载和内存等常见读数通常可以在普通权限下获取，具体项目取决于设备和驱动。若出现「需管理员」，可在设置面板的「状态」页选择「以管理员身份重新启动」；也可以退出挂件后，右键 `EndfieldMonitor.exe`，选择「以管理员身份运行」。部分 CPU 温度、功率和频率等读数还需要 [PawnIO 驱动](https://pawnio.eu/)；本程序不安装该驱动。管理员权限也不保证每台电脑都能提供同样的读数，存储传感器只在管理员模式下尝试采集。

中央电量显示使用 Windows 提供的实际百分比，不会把设置的充电上限视作 100%。接通电源但没有充电时显示「已接电，未充电」；没有电池的机器会显示「未检测到电池」，不会显示成 0%。剩余时间只有在系统提供有效估计时才显示。

### 配置与常见问题

- **配置存在哪里？** 默认是 EXE 同目录的 `EndfieldMonitor.settings.json`；该目录不可写时使用 `%LOCALAPPDATA%\EndfieldMonitor\`。以设置面板「状态」页显示的路径为准。退出程序后可备份或移走此文件，下一次启动会重新使用默认设置。
- **为什么某些读数不可用？** 除了权限和驱动，休眠中的独显、固件不支持或设备变动也可能让传感器暂时不可用。若设备已经更换，可重新选择传感器。当前版本不采集网络适配器传感器。
- **如何减轻动画开销？** 可在「显示」页关闭粒子动画，或者降低挂件缩放。隐藏时动画停止，系统关闭「显示动画」时黑弧和粒子也会保持静止。

## 从源码开发和构建

需要 Windows x64 和 **.NET 10 SDK 或更新的兼容 SDK**。在项目根目录打开 PowerShell，执行以下命令：

```powershell
# 构建并运行单元测试
dotnet test .\EndfieldMonitor.slnx

# 构建并运行 Debug 版本
dotnet run --project .\src\EndfieldMonitor.csproj
```

也可以直接在 Visual Studio 中打开解决方案进行调试与发布。

如要公开分发构建产物，请先核对实际随包组件，并将项目许可证和第三方组件所需的许可证、声明及对应源码获取方式一并提供。不要只分发 EXE 而省略这些文件。

| 位置 | 内容 |
| --- | --- |
| `EndfieldMonitor.slnx` | 解决方案，包含主程序与测试两个工程 |
| `src/` | WPF 界面与绘制、Windows 窗口和托盘集成、硬件采集与配置 |
| `tests/` | 电池、传感器、配置、窗口位置和绘制等逻辑的 xUnit 测试 |

### 开发排查

- 重新构建前先退出挂件；如果报 `MSB3027`，先确认没有运行中的调试实例占用 EXE。
- 主工程固定使用 `win-x64`，以便加载 LibreHardwareMonitorLib 的运行时实现。
- 设置 `ENDFIELD_TRACE=1` 可在 EXE 同目录写诊断日志；`ENDFIELD_BAND_FPS` 可用 5–60 覆盖默认黑弧帧率（20）；`ENDFIELD_RENDER=sw` 可强制软件渲染。退出旧实例后，用 `--snapshot <png>` 启动可导出带底色和透明底的仪表图，再自动退出。
- 管理员传感器实测、多显示器与混合 DPI、无电池台式机、独占全屏置顶、系统动画开关切换，以及小比例下的屏幕边缘弹窗定位，仍待更广泛的实机验证。
